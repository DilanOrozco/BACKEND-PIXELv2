PAGINACION BACKEND PIXEL

La paginacion ahora la maneja el backend, no el frontend.
El frontend solo debe enviar parametros por query y mostrar la respuesta.

ENDPOINTS CON PAGINACION

Los listados principales soportan paginacion:

- GET /api/usuarios
- GET /api/roles
- GET /api/tecnicas
- GET /api/proveedores
- GET /api/pedidos
- GET /api/cotizaciones

PARAMETROS DISPONIBLES

page:
Numero de pagina que se quiere consultar.
Ejemplo: page=1

limit:
Cantidad de registros por pagina.
El backend permite maximo 10 registros por pagina.
Aunque el frontend envie limit=50, el backend lo recorta a 10.

search:
Texto de busqueda.
Se combina con la paginacion, pero la busqueda ocurre en base de datos.
No se traen todos los registros para filtrar en frontend.

sortBy:
Campo por el cual ordenar.
Solo se aceptan campos seguros definidos por el backend.

order:
Orden de los resultados.
Valores permitidos:
- asc
- desc

EJEMPLO DE REQUEST

GET /api/usuarios?page=1&limit=10&search=juan&sortBy=nombre&order=asc

EJEMPLO DE RESPUESTA

{
  "data": [],
  "meta": {
    "page": 1,
    "limit": 10,
    "total": 35,
    "totalPages": 4,
    "hasNextPage": true,
    "hasPrevPage": false
  }
}

COMO USARLO EN FRONTEND

data:
Lista de registros que se muestran en la tabla.

meta.page:
Pagina actual.

meta.limit:
Cantidad de registros por pagina.
Siempre sera maximo 10.

meta.total:
Total real de registros encontrados en base de datos para esa busqueda.

meta.totalPages:
Cantidad total de paginas disponibles.

meta.hasNextPage:
Sirve para habilitar o deshabilitar el boton "Siguiente".

meta.hasPrevPage:
Sirve para habilitar o deshabilitar el boton "Anterior".

EJEMPLOS

Listar primera pagina de usuarios:
GET /api/usuarios?page=1&limit=10

Buscar usuarios por nombre:
GET /api/usuarios?page=1&limit=10&search=juan

Ordenar usuarios por nombre:
GET /api/usuarios?page=1&limit=10&sortBy=nombre&order=asc

Buscar pedidos pendientes:
GET /api/pedidos?page=1&limit=10&search=pendiente

Buscar pedido por numero:
GET /api/pedidos?page=1&limit=10&search=123

IMPORTANTE

- El frontend no debe paginar arrays completos.
- El frontend debe pedir cada pagina al backend.
- La busqueda y la paginacion funcionan juntas.
- El backend usa count, where, skip y take en Prisma.
- No se cargan todos los registros para buscar o paginar.
- El maximo por pagina es 10 registros.
